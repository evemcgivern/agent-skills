# Role separation and filenames

## Candidate and target identity

Before naming downloads, confirm candidate first/given and last/family name from the source resume where unambiguous. Ask about missing names, unclear order/spelling, or a redacted/mononym candidate's preferred file label. Never substitute the account owner's identity or invent a surname. Preserve the candidate's display name inside the document. Confirm original resume, complete JD, employer, official vacancy title, requisition ID, source label/link, and distinguishing details. Resolve conflicts with the candidate, not upload names.

## Role isolation

Multiple JDs do not automatically mean a batch. Ask which role or whether one version per role is wanted. After an explicit batch request, create one resume, one separate note set, and (when requested) a cover letter for each confirmed role. State targets briefly. Never blend JDs, turn requirements into qualifications, or transfer company-specific answers/motivation across roles.

For a later role in the same chat, use the original resume and applicable confirmed factual answers only when reuse is clear. Never use a previous tailored resume as the master. If the original is unavailable, request it again. Preserve provenance, scope, and certainty for reusable facts; clarify uncertain applicability. Rebuild evidence maps and gaps for every JD. Run clarity review and preflight for each role and rendition; one role's PASS does not apply to another. Continue confirmed work when another role is awaiting facts. No application or external transmission is authorized by document preparation.

## Default filenames

Follow explicit employer/user naming instructions first, subject to safe paths and truthful extensions. Otherwise use:

```text
Last_First_Employer_Role_Resume_v01.docx
Last_First_Employer_Role_Resume_v01.pdf
Last_First_Employer_Role_CoverLetter_v01.docx
Last_First_Employer_Role_CoverLetter_v01.pdf
Last_First_Employer_Role_Notes_v01.txt
Last_First_Employer_Role_Resume_Draft_v01.docx
```

Use confirmed names, employer and role. Ask for a confirmed or user-chosen label if the employer/title is missing; drafting can continue while role-named file creation waits. Shorten role/employer meaningfully, preserve the full official vacancy title in notes and original employment titles in resume. Add a supplied requisition ID when needed. For same employer/title without IDs, ask for team/location or agree on Role1/Role2 and record mapping. Never invent IDs.

Use ASCII letters/digits, underscores and hyphens, with only the extension dot. Sanitize punctuation and spaces consistently. No separators, `..`, control characters, reserved OS names (`CON`, `PRN`, `AUX`, `NUL`, `COM1`, `LPT1`), trailing dots/spaces, or unnecessary contact/account/health data. Aim for <=100 characters before extension as a product convention, not an ATS rule. Check uniqueness after sanitizing/truncating, including case-insensitive collisions. Never overwrite silently. Increment v01/v02 for same-role revisions; if version is unclear, choose a distinct name. Avoid `final_final`.

DOCX/PDF variants of the same resume revision share a basename; cover letters use a distinct `_CoverLetter_` basename. Notes use matching identifiers/version with `Notes`. Extensions must match actual file format. Remove Draft only after required checks pass. Text-only output names role/status without implying there is a download. Before delivery, compare filenames and actual contents with candidate, JD, revision and status, and check for cross-role contamination. The two-page limit applies per resume; notes are separate.
