# Resume format

This is a presentation default, not a source of candidate facts. The candidate may request another style. Populate only from the current candidate's source ledger. Preserve distinctive, supported achievements and context; remove duplication before cutting unique relevant evidence. Ask about unclear facts. Never infer content from a sample resume.

## Section order and content

1. Center the candidate's name, bold, 17 pt, navy. Use confirmed spelling/capitalization.
2. Center one compact contact line with only supplied location, phone, email, professional profile. Separate with ` | `; omit missing fields and dangling separators. Keep link text visible in the document body.
3. Center an uppercase, bold, navy specialty line using supported strengths relevant to the role, separated by ` · `. It is not a new employment title and must not echo every JD keyword. Add a thin navy bottom border.
4. Add one concise opening profile paragraph of at most 3 rendered lines and 60 words, no “Summary” heading by default. Use direct, concrete supported scope, work, and outcomes. First-person narrative is the default unless candidate requests another voice. Do not invent total years or achievements. Write the profile, specialty line and capability groups only from the source ledger and the source's own words. Tense must match the role's dates: past tense for ended roles, present tense only for the current role. Never merge facts from different roles into one claim, and never add a headline term or skill label the source does not use. Every term in the specialty line and the capability labels must use words that appear in the source resume or the confirmed pack facts. A term that only appears in the posting, or a noun or verb form derived from a source word (for example 'reconciled' does not support 'reconciliation'), does not qualify. Never tell the candidate the line uses only their terms unless that is true. This covers the specialty line (item 3) and capability groupings too.
5. `CORE CAPABILITY` (optional): at most 3 grouped lines with bold category labels followed by supported capabilities separated by ` | `. Choose categories for this candidate. Include only terms the posting uses that have direct evidence, never a list that repeats the bullets, and omit the section if it cannot meet this.
6. `PROFESSIONAL EXPERIENCE`: reverse chronological. Role line: bold official title, employer/location, bold dates; use supplied date precision. Keep the dates in the same paragraph, after the right tab. If a long title/employer wraps, the dates sit at the right margin of its last line; if they do not fit beside that line they drop to a line of their own. Do not split the dates into a separate paragraph. Add brief gray italic context only when supported. Use round achievement/responsibility bullets. Keep role line, context, and first bullet together. Older positions may be summarized under a bold `Earlier:` label when material facts and chronology remain clear.
7. Optional `SHIPPED PRODUCTS & OPEN SOURCE` only for supported, relevant shipped/open-source work. Use project names and supported descriptions. Use `PROJECTS` for other projects. Omit unsupported sections.
8. Optional `TECHNICAL`: grouped tool/skill lines with bold labels and ` | ` separators. Avoid duplicating all capability terms; omit if unsupported.
9. Select education/credential heading from actual entries:
   - Education/programs/coursework and no certifications: `EDUCATION`.
   - Certifications and no education: `CERTIFICATIONS`.
   - Both: `EDUCATION & CERTIFICATION`.
   - Neither: omit the entire section and all sublabels.
   A course is not automatically a certification. Preserve exact names and classification; ask if materially ambiguous. In-progress certifications may determine the heading but must remain marked unearned. A `Certifications:` sublabel appears only for earned certificates; an `In progress:` line only for explicitly supplied ongoing ones. Never infer a credential from the JD.

Keep questions, job-fit notes, evidence references, change notes, and missing qualifications outside the resume. Never add an empty heading or placeholder.

## DOCX defaults

| Element | Default |
|---|---|
| Page | US Letter, portrait |
| Margins | 0.5 in top/bottom; 0.625 in left/right; never below 0.5 in |
| Typeface | Calibri; metrically similar sans serif only if unavailable |
| Body/supporting text | 11 pt, black, left aligned; single spacing |
| Name | 17 pt, bold, navy `#1F3864`, centered; 1 pt after |
| Contact | 11 pt, centered; 1 pt after; visible link text |
| Specialty | 11 pt, bold, navy, centered; 4 pt after; thin navy bottom paragraph border |
| Profile | 11 pt; 1.0 line spacing; 3 pt before/after |
| Section headings | 11 pt, bold, uppercase, navy; 6.5 pt before, 2.6 pt after; 0.75 pt gray `#808080` bottom paragraph border, 2 pt border spacing |
| Grouped capability/technical/education lines | 11 pt; bold category label, regular values; 1.0 line spacing; 0 pt before, 2.2 pt after |
| Role line | 11 pt; bold title and dates; regular employer/location; 5.2 pt before, 0.4 pt after; right tab at the text width (7.25 in on US Letter with 0.625 in side margins; recompute if margins change), no leader if available |
| Context | 11 pt, italic, gray `#404040`; 1.0 line spacing; 0 pt before, 2.5 pt after |
| Bullets | 11 pt, black; 1.0 line spacing; 0 pt before, 1.4 pt after; left indent 0.15 in, hanging indent 0.125 in; real Word list numbering |
| Earlier-career paragraph | 11 pt; bold introductory label; 1.0 line spacing; 5 pt before, 2 pt after |

Use editable paragraphs/runs, paragraph borders and defined styles. Do not make layout out of images, tables, floating shapes, text boxes, or columns. Do not put important text or contacts in headers/footers. Keep headings with next paragraph; avoid separated role headings and unnecessary bullet splits without keeping entire long experience sections together and creating blank space. Do not add repeating contact headers or page furniture by default.

If a font substitution or candidate content creates clipping, fix wrapping/pagination first and increase type size or line spacing as needed for legibility. Keep bullets together where practical without creating large blank areas. Use these compact reference measurements as starting points, then judge the rendered document.

## Length and accessible fallback

Apply SKILL.md's skim-readability budget first (550 to 750 words, never over 850; bullets of at most 2 lines; bullet counts per role); it is a separate limit from the page count. Maximum two **rendered resume pages**; one is fine. Start at 11 pt and maintain >=0.5 in margins and >=single spacing. Only for a few overflow lines try 10.75, then 10.5 pt if needed. Keep the largest size that passes. No text, including contacts, below 10.5 pt. Rerender, recount and inspect after each adjustment. For substantial overflow, first condense repetition and lower-priority wording, preserving unique evidence and qualifiers. If still too long, cut whole lines by score, following SKILL.md's length and presentation gate (a tie is never a reason to ask). Never call an overlength document compliant.

Plain text uses the same information order, uppercase section labels, grouped labels, role/employer/location/date order, context and bullets; visual styling can be omitted. Deliver a complete copyable resume without requiring paid tools. Plain text cannot verify pagination. Disclose formatting limits outside the resume.

## Final check

Apply the checklist in SKILL.md's length and presentation gate to each delivered DOCX/PDF. Extract each rendition including link labels and compare order, contacts, names, titles, dates, credentials, and bullets to the source ledger. Recompute credential headings from final entries. Verify actual Word numbering indentation as well as style indentation. If rendering or extraction is unavailable, report exactly what is UNVERIFIED and label the artifact Draft. Never claim ATS certification.
